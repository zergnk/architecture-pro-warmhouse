# Задание 1. Анализ и планирование

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут управлять отоплением в нескольких домах,  подключенных к системе "Умный Дом"
- Пользователи могут включать и выключать отопление в доме.
- Пользователи могут устанавливать желаемую температуру в каждом помещении дома.
- Система поддерживает регулировку температуры посредством управленияе датчиками температуры и реле, 
включающими и отключающими нагревательный элемент и насос. 

**Мониторинг температуры:**

- Пользователи могут просматривать текущие значения температуры в разных помещениях своего дома,
- Система поддерживает автоматический сбор текущих значений температуры посредством периодических запросов к датчикам 
температуры, установленным в помещениях дома.

**Подключение, отключение и настройка устройств**

- Технические специалисты могут подключить датчики температуры и реле управления обогревателем и насосом 
в системе отопления к системе "Умный Дом".
- Система поддерживает подключение только датчиков температуры и реле управления обогревателем и насосом.


### 2. Анализ архитектуры монолитного приложения

**Архитектура**

- Архитектура системы представляет собой монолит, все компоненты системы (обработка запросов, бизнес-логика, работа 
с данными) находятся в рамках одного приложения. Система взаимодействует с базой данных.
- Взаимодействие: Синхронное, запросы обрабатываются последовательно. Запросы выполняет система.
- База данных: Postgresql
- Язык программирования: Go

### **4. Проблемы монолитного решения**

- Масштабируемость: Ограничена, так как монолит сложно масштабировать по частям.
- Развертывание: Требует остановки всего приложения.
- В случае роста системы в связи с реализацией нового функционала будет замедляться выпуск новых версий, т.к.
нужно синхронизировать деятельность разработчиков.
- Регрессионное тестирование монолита может сильно замедлить скорость выпуска новых версий, а также требует
дополнительных усилий команды QA.
